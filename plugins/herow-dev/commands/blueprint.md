## Initial setup (do this first, in order)

**Convention used throughout this file:** shell variables never survive between separate
Bash tool calls. Rather than trust that two steps land in the same call, every snippet
below that needs `$PLANS` or `$ACTIVE_DIR` **re-resolves it inline** — `herow-project.sh`
is idempotent and cheap (a repeat `--ensure` on an unchanged repo is a no-op), so this is
safe to call as many times as needed. `<PLANS>`, `<SLUG>`, `<ACTIVE_DIR>` in prose (angle
brackets) mean "the absolute value you resolved," never a literal shell variable.

0. **Pull latest first (fail-open, automatic).** A `UserPromptSubmit` hook (`scripts/pull-latest.sh`) fast-forwards the current branch to its upstream (`git pull --ff-only`) on the main tree **before** this command runs, so planning always reflects the freshest code. It's fail-open (offline/detached/no-upstream/diverged all warn and continue, never block) and opt-out via `HEROW_SKIP_PULL=1`. You don't invoke it — just be aware the base is already fresh.
1. **Resolve and print `<PLANS>`, then sweep dead session markers** (inert, but they
   accumulate — the marker directory is shared across every project, one level above
   `projects/<id>/`):

   ```bash
   PLANS="$(bash "${CLAUDE_PLUGIN_ROOT}/scripts/herow-project.sh" plans --ensure)"
   echo "PLANS=$PLANS"
   ACTIVE_DIR="$(dirname "$(dirname "$PLANS")")/.active"
   find "$ACTIVE_DIR" -maxdepth 1 -type f -mtime +7 -delete 2>/dev/null || true
   ```
   This also runs the one-shot legacy migration (moves an existing `.claude/plans/*` in this repo into the store; a git-tracked `.claude/plans` is left in place with a warning printed to stderr — surface that warning to the user if it appears). It never creates anything outside `$HEROW_HOME`. **Read the printed `PLANS=` value and use it as `<PLANS>` in every command below** — don't assume a bare `$PLANS` will still be set in a later Bash call.
2. Generate the plan slug: `TS=$(date -u +%Y%m%d-%H%M%S)`, kebab-case slug from the description (max 40 chars, only `[a-z0-9-]` — keep it filesystem- and branch-name-safe, since `/herow-dev:execute` turns it into `<type>/<slug>`), `SLUG="${TS}-<slug>"`. This `SLUG` is the name of the plan's **directory** — remember it verbatim for every later step, it's never re-derivable from anything.
3. **Claim the plan directory as an atomic uniqueness claim** — `mkdir` **without** `-p`.
   Re-resolve `$PLANS` in this same call (it may be a different Bash call than step 1's):

   ```bash
   PLANS="$(bash "${CLAUDE_PLUGIN_ROOT}/scripts/herow-project.sh" plans --ensure)"
   until mkdir "$PLANS/$SLUG" 2>/dev/null; do SLUG="${SLUG}-2"; done
   mkdir -p "$PLANS/$SLUG/artifacts"
   echo "PLAN_DIR=$PLANS/$SLUG"
   ```
   `mkdir` is atomic at the filesystem level: if the directory already exists (same-second + same-slug collision across parallel sessions), the loop picks a new suffix — if that happens, `SLUG` changed; use the printed `PLAN_DIR=` value (and update your remembered `SLUG`) from here on. **Never** use `mkdir -p` for the claim.
4. **Activate the harness tracker (session-scoped marker).** Bash exposes the session id
   as `CLAUDE_CODE_SESSION_ID` (equal to the hook payload's `session_id`); the legacy
   `CLAUDE_SESSION_ID` below is only a fallback. The marker holds the plan directory's
   **absolute path** (not just the slug) — re-resolve `$PLANS` again in this same call:

   ```bash
   SID="${CLAUDE_CODE_SESSION_ID:-$CLAUDE_SESSION_ID}"
   PLANS="$(bash "${CLAUDE_PLUGIN_ROOT}/scripts/herow-project.sh" plans --ensure)"
   ACTIVE_DIR="$(dirname "$(dirname "$PLANS")")/.active"
   if [ -n "$SID" ]; then
     mkdir -p "$ACTIVE_DIR"
     printf '%s\n' "$PLANS/$SLUG" > "$ACTIVE_DIR/$SID"
   else
     echo "Tracker disabled: no session id available — state.json won't auto-populate; build the gstack Artifacts section manually at consolidation."
   fi
   ```
   An empty `SID` writes **no** marker. The marker is tied to **your** session (`$SID`), so
   parallel blueprints (even across different repos) **don't collide** and the hook never
   logs another session's skills against this plan. From here on, the herow-dev plugin's
   `PostToolUse:Skill` hook (`blueprint-track.sh`) automatically logs each executed skill
   to `<PLANS>/<SLUG>/state.json`; artifacts are detected by mtime diffing **inside
   `<PLANS>/<SLUG>/artifacts/`** — write any orchestration output you want tracked there.
   You **don't** need to take manual snapshots.
5. **Don't create `plan.md` now.** `plan.md` is written exactly once, at final consolidation — its absence marks a plan as still in progress, so an aborted blueprint is never resolved by `/herow-dev:execute`.

## Final consolidation

Order matters — the tracker (`$HEROW_HOME/projects/.active/$SID`, when a session id was available) stays active until step 7, so that skills triggered in step 4 also get logged.

1. **Read state.json:** re-resolve `$PLANS` (same command as Initial setup step 1) in this
   call, then `cat "$PLANS/$SLUG/state.json"` — contains the list of executed skills
   (`skills[].skill`, already normalized without namespace/leading slash: e.g.
   `office-hours`) and detected artifacts.
   - **If state.json doesn't exist** (hook not registered or failed): warn explicitly, build the "gstack Artifacts" section manually from the outputs you observed each skill produce, and mark as ✅ in the checklist below the steps you know ran in this session.
2. **Coverage checklist (always show to the user):** compare state.json against the canonical list and show each step with one of these states:
   - ✅ executed — present in state.json
   - ⬜ not executed — applicable, but didn't run
   - ➖ not applicable — condition doesn't apply (e.g. `/plan-design-review` without UI, `/plan-devex-review` without API/SDK/docs) — include the reason in 1 line

   Canonical list: `office-hours`, `plan-ceo-review`, `plan-eng-review`, `plan-design-review` (conditional on UI), `plan-devex-review` (conditional on API/SDK/docs), `spec` (optional).
3. **Offer to trigger the missing steps** — `AskUserQuestion` with `multiSelect: true`:
   - One option per step not executed (include the ➖ ones too, labeled "not applicable"), with a 1-line description of what the skill adds.
   - If only **one** step is missing, add a second option "None — finalize the plan" (the question requires ≥2 options).
   - If **zero** steps are missing, skip the question.
4. **Run the selected skills** (the tracker is still active, so they land in the same state.json) and **re-read state.json**.
5. Re-resolve `$PLANS` (same command again), then use the final artifact list to fill in
   the plan's "gstack Artifacts" section (paths + role of each). If there was source
   material, save it to `$PLANS/$SLUG/source.md`.
6. **Write the plan** — re-resolve `$PLANS` once more in this call — to `$PLANS/$SLUG/plan.md` (once — this is what marks the plan as ready for `/herow-dev:execute`). There is **no** more `latest.txt`: `/herow-dev:execute` resolves the most recent plan by directory, and you print the exact command in the final report.
7. **Deactivate the tracker and clean up snapshots.** Shell variables don't survive between
   Bash tool calls, so recompute `SID` and `$PLANS` in this same call rather than relying
   on an earlier step's:

   ```bash
   SID="${CLAUDE_CODE_SESSION_ID:-$CLAUDE_SESSION_ID}"
   PLANS="$(bash "${CLAUDE_PLUGIN_ROOT}/scripts/herow-project.sh" plans --ensure)"
   ACTIVE_DIR="$(dirname "$(dirname "$PLANS")")/.active"
   [ -n "$SID" ] && rm -f "$ACTIVE_DIR/$SID"
   rm -rf "$PLANS/$SLUG/.snap"
   ```
   (important — otherwise future skills in this session would keep being logged against this plan).
